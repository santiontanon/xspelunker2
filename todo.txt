PCG structure:

PCGWorld: 
1.- generateAreaLayouts:
  - for each area: generateArea
    - if layout is not prespecified: start from the center, and randomly grow out until 0.5 of the area is used
2.- generateDivisions
  - set predefined divisions (in "confluence")
  - add minimum number of division seeds to each area (without repeating any)
  - randomly distribute the other division seeds
  - for each area: floodFillDivisionIDs
    - "open" list with all the seeds: start filling neighboring (picking random points from this open list as the next)
4.- generateAreaConnections:
  - using "randomAreaBottomMostPoint"-like functions, pick connection points, and add to the list of "connections"
5.- generateSpanningTree
  - randomAreaLeftMostPoint to get the starting point/division
  - open list with that initial division
  - then iterate until open is empty, removing one at random and adding all the neighbors with "getDivisionNeighborPoints"
  - Result is a spanning tree, which could be encoded in assembler as just an array of "AreaDivision" structs
6.- generateMission
  - boss1, ..., boss5, midpoint, ending: sampling divisions (favoring or requiring leaves)
  - generate quest specs for boss1, 2, 3, midpoint and ending
  - generateSubquests:
    - while there are quest specs:
      - get the first quest spec from open
      - choose a type (a-to-b, obstacle, key-chestlock, key-lock): if 0 subquests just a-to-b, if a boss quest, force chest-lock. Also if there are no locks/keys left for one type, ignore it
      - if the lock_tag is not specified in the quest spec, pick one at random of the appropriate type, not used before
        - ...
      - addTags: if there is a tag there that is incompatible, FAIL!
  - generate quest specs for boss 4, 5
  - generateSubquests (same as before, but with different reachable/useable area)
  - set "lockKeys" to all the used locks and keys (not needed in assembler, only used for debugging)

PCGArea:
0.- mergeAreaRooms
  - for each position in the map, random change to merge with up/down/left/right as long as it's within division, and as long as room area is <= 4 (how do I track this in assembler? maybe a room list?)
1.- Generate a spanning tree for each division:
  - The result is that "pieceTypes" has all the connections necessary for this spanning tree
2.- Complement "pieceTypes" with the "a.connections" generated by PCGWorld
3.- Add random paths (note: 2 & 3 can be done in the same loop)
4.- Place tags (assign room tags to a single chunk position, only one tag per chunk)
5.- Choose chunks. For each position in the map (chunk-level):
  - Determine the constraints on the chunks (pool, tags, locations it must have)
  - Choose a chunk
  - Add necessary objects according to the tag (if any)
